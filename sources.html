Reproducibility

Four levels: file integrity through independent implementation

LevelMeaningExample
R1 · IntegrityReleased artifact can be hash-checked and consumed deterministically.ERA5-sensitive v2 hourly payload.
R2 · TransformationRetained inputs + code regenerate a derived artifact.Most historical/model transformations.
R3 · Source-to-resultAcquisition + transformation + model reproduce a result, subject to upstream access.Several source-bounded model chains.
R4 · Independent implementationSeparate implementations reproduce the same mathematical result.PyPSA/SciPy and PyPSA/OSeMOSYS common formulations.
Known gap: the original ERA5-sensitive v2 hourly-shape fitting script and raw ERA5 archive are not committed. The released chronology is integrity-verifiable, but that original hourly fit is not fully source-to-fit reproducible from a fresh clone.
The newer observed-daily ML v0.1/v0.2 chain is separately reproducible: GitHub Actions re-downloads the verified FY2024–25 ERA5 source artifacts, re-runs source QA, rebuilds the weather table, tunes LightGBM/XGBoost with Optuna, evaluates chronological holdouts and generates conditional SHAP outputs. The frozen v0.2 evidence records the reference workflow run and artifact digest.
